# Bulba Battle — Product Requirements Document

Ретро 8-битная браузерная артиллерийская дуэль по мотивам классических
Worms. Играть можно прямо сейчас: **https://webeasy35-png.github.io/worm-duel/**

## 1. Контекст создания

Проект родился как домашнее задание к 2-му уроку курса по Claude Code —
практика итеративной разработки в диалоге с агентом (фича за фичей,
тестирование, подтверждение, следующая фича). Это не отменяет того, что
игра — полноценный, реально играбельный продукт, а не одноразовое
упражнение: она развивается дальше и после того, как урок формально сдан.

## 2. Видение продукта

Bulba Battle — это лёгкая, ностальгическая пошаговая дуэль червей (по духу
исполнения персонажи вышли настолько круглыми и клубнеобразными, что
корректнее уже называть это дуэлью картофелин), в которую можно зайти по
ссылке без установки, без регистрации и без интернет-магазина внутри, и за
5-10 минут получить весёлую партию — либо против бота, либо (в будущем)
вместе с другом. Игра ценит атмосферу и юмор ретро-аркад больше, чем
глубину баланса или киберспортивную честность.

## 3. Целевая аудитория

Друзья и знакомые автора, а также, есть надежда, другие участники курса по
Claude Code — как пример того, что можно сделать за несколько итераций.
Не массовый продукт и не портфолио-витрина — цель не «зацепить незнакомого
игрока за 10 секунд», а дать конкретным людям повод посмеяться вместе.
Отсюда следствия для приоритетов:

- Понятность важнее глубины обучения — не нужен туториал для случайного
  прохожего, но управление должно быть очевидно другу за столом.
- Юмор и мемность (голосовые реакции, анонсы, «Помидор») — не второстепенная
  полировка, а часть ценности продукта.
- Не нужно оптимизировать под широкую публику (SEO, онбординг, соцсети).

## 4. Статус

**v1.0 — фактически готова.** Текущий набор фич (см. раздел 6) считается
завершённой первой версией продукта. Дальнейшая работа — это либо полировка
существующего, либо осознанное расширение по одному из направлений roadmap
(раздел 8), а не догон до какого-то ещё не реализованного минимума.

## 5. Основной игровой цикл

1. Игрок выбирает сложность соперника и жмёт Enter — старт матча.
2. По очереди (игрок ↔ ИИ) активный червь двигается, прицеливается, выбирает
   оружие и стреляет, либо отступает после выстрела в окне 5 секунд.
3. Взрывы разрушают рельеф, наносят урон, могут задеть мины/бочки с
   напалмом и вызвать цепную реакцию.
4. Матч идёт до победы одной из команд (все черви соперника мертвы) либо до
   внезапной смерти — по истечении лимита времени матча поднимается вода и
   топит отстающих.
5. Экран победы/поражения → рестарт на новый (процедурно другой) рельеф.

## 6. Функциональные требования (реализовано в v1.0)

**Управление и черви**
- Движение по разрушаемому рельефу, прицел, набор силы удержанием, прыжок
  с рулением в воздухе (Shift).
- 6 червей на команду (по 2 сейчас), ротация активного червя по очереди,
  индивидуальные имена, числовой HP, визуальные аксессуары (кепка, бандана,
  очки, ирокез) для узнаваемости.

**Оружие**
- Базука (мгновенный взрыв при контакте) и граната (отскок + фитиль),
  визуально узнаваемые в руках червя, поворачиваются по прицелу.
- Супер-граната «Помидор» — редкая награда с ящика.

**Хазарды карты**
- Мины: срабатывают по близости, гравитация как у червя, завершают ход
  только если кого-то задело.
- Бочки с напалмом (3-5 на карту): взрыв при попадании или по цепной
  реакции от другого взрыва, оставляют горящую зону с уроном по времени.
- Вода: постоянная у подножия карты (утопление при пробитии рельефа
  насквозь) + внезапная смерть с подъёмом воды после лимита времени матча.

**ИИ-соперник**
- 3 уровня сложности. Баллистика с управляемым шумом (не идеальная, не
  нулевая точность), решение об отходе по причине (скученность с
  напарником или обрыв — не бессмысленное каждый ход), сохраняет верный
  прицел после манёвра отхода.

**Аудио**
- Полностью процедурная 8-битная озвучка (Web Audio API, без файлов):
  выстрелы, взрывы, прыжок, попадание с комедийным голосовым вскриком,
  подбор ящика, тревога мины, смена хода, победа/поражение, фоновая
  зацикленная музыка. Мьют на клавишу `M`.

**HUD и интерфейс**
- Три зоны HUD (ход+таймер с секундами / ветер / оружие+опасность), таймер
  хода 45с со сбросом на 5с при выстреле, компактное главное меню (выбор
  сложности в одну строку, подсказки управления в рамке).
- Ретро-ТВ рамка вокруг экрана, скан-линии, ограниченная 8-битная палитра.

**Ящики с наградами**
- Контейнер на парашюте, редкий спавн (раз в 3 хода, 20% шанс), тип
  (аптечка/оружие) решается при спавне.

## 7. Технические ограничения (не подлежат пересмотру)

- Один файл `index.html` — HTML5 Canvas + vanilla JS, без сборки, без
  фреймворков, без внешних библиотек.
- Никаких сетевых загрузок: ни шрифтов, ни картинок, ни звуковых файлов —
  вся графика и звук генерируются в коде.
- Работает полностью в браузере, без сервера/бэкенда, без аккаунтов.
- Файл обязан лежать в корне `Game/` под именем `index.html` (требование
  GitHub Pages, деплой — просто пуш в master).

## 8. Roadmap (следующие направления)

Порядок не приоритет — решаем по одному пункту за раз по факту готовности:

1. **Больше оружия** — расширить арсенал за пределы базуки/гранаты/супер-
   гранаты. Вместе с этим — пересмотреть выбор оружия (сейчас клавиши `1`/
   `2`, при росте арсенала нужен другой UX, возможно меню-сетка как в
   Worms — решаем в момент добавления реального нового оружия).
2. **Мультиплеер** — сейчас только игрок против ИИ. Формат (хотсит на одной
   клавиатуре vs. сетевой) не определён, требует отдельного обсуждения.
3. **Мобильная/сенсорная версия** — сейчас управление только с клавиатуры,
   с телефона играть нельзя. Нужны сенсорные элементы управления без
   потери минималистичности интерфейса.
4. **Полировка текущего** — баланс, звук, визуал, баги — без новых крупных
   механик.

## 9. Вне скоупа (осознанно не делаем)

- Бэкенд, аккаунты, облачные сохранения, лидерборды.
- Монетизация в любом виде.
- Массовый онбординг, локализация на другие языки, SEO/маркетинг.
- Внешние ассеты (шрифты, спрайты, звуки, библиотеки) — принципиальное
  ограничение проекта, не техдолг.

## 10. Метрика успеха

Формальных метрик (DAU, retention и т.п.) нет и не нужно — аудитория
приватная. Продукт считается успешным, если друзьям, которым скинута
ссылка, реально весело сыграть партию-две.
